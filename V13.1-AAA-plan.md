# NVH Spectro — Plan: V13.1 → AAA

**Input:** `V13.1-audit.md` (74 findings: 4 Critical / 22 High / 30 Medium / 18 Low) and the code at commit `4518ec6`.
**Goal:** the shipping app earns A− or better in every audit category, verified by measurable gates — not by assertion.
**Date:** 2026-08-26

> Scope note: this plan brings the **V13.1 codebase at the repo root** to AAA. If the team instead designates the `v2/` rewrite as the shipping vehicle, Phases 1–2 of this plan become its acceptance-requirements spec verbatim; the sequencing logic is the same.

---

## 0. Guiding principles

1. **Measurement and kinematic precision outrank UI polish.** Phase order reflects this: the numbers become trustworthy before anything becomes prettier.
2. **Strangler refactor, not big-bang.** The app stays shippable at the end of every phase. No phase leaves `master` broken for more than a day.
3. **Characterize before refactoring.** Golden-file tests pin current behavior *before* code moves, so every refactor diff is provable. Where current behavior is a bug (C1, C17…), the golden test pins the *corrected* expected value, derived analytically.
4. **On-device verification gates.** This project has already proven that green unit tests can miss crashes and layout bugs. Every phase ends with a written device checklist executed on real hardware before the phase is called done.
5. **One finding, one owner step.** All 74 audit findings are mapped to a phase step in §9 (traceability). Nothing is "generally addressed."

## 1. Definition of AAA — acceptance gates

The audit scorecard becomes the exit criteria. Each gate is checkable, not aspirational.

| Category (audit grade) | Target | Exit gate — measurable |
|---|---|---|
| DSP / measurement (D+) | **A** | Reference-tone suite passes at 44.1 / 48 / 96 kHz: displayed frequency within ±Δf/2, level within ±0.5 dB (scalloping-corrected); TTNR either ECMA-74-conformant or renamed in every UI/PDF surface; written error-budget doc (speed → order-frequency) shipped in `doc/` |
| Architecture (D) | **A−** | `MainViewModel` < 300 lines; pure-Kotlin `:core` module with zero Android imports; one `OrderTrackingEngine` used by live + sweep; zero dead files (CI grep gate) |
| Concurrency (D−) | **A** | StrictMode clean (no main-thread I/O); method-trace shows zero FFT frames on main; LeakCanary clean over a 10-min session incl. 10 mode switches; mic indicator off outside LIVE mode |
| Performance (D+) | **A−** | Macrobenchmark: live view ≤ 5 % janky frames on a mid-range device; 5-min WAV: load+render < 3 s, peak heap < 256 MB; no per-frame allocation in the render loop (allocation tracker) |
| Compose/UI (C−) | **A−** | No `System.currentTimeMillis()`/side effects in composition (lint rule); all canvas geometry in dp/sp; zoom keeps overlays aligned (screenshot test); both permission-denial paths usable |
| Data & storage (D) | **A−** | Settings + kinematics survive process death (test); telemetry schema v2 with version field + v1 migration test; every save/load failure surfaces a user-visible message |
| Security/privacy (C+) | **A** | INTERNET permission still absent; mic/GPS active only when their mode is; no JS WebView; error log is local-only with explicit share action |
| Build/release (D) | **A** | Version single-sourced; CI runs unit + lint + detekt + **minified release** assemble + install smoke on every push; repo free of binaries/scratch (CI gate) |
| Testing (F) | **A−** | `:core` ≥ 90 % line coverage; §10 test floor implemented; every P0/P1 fix has a regression test named after its finding ID |
| Docs (C−) | **B+** | README + architecture doc regenerated from the real code; DSP methods doc states actual algorithms and deviations from standards |
| A11y / i18n (F) | **B** | All strings in `strings.xml` (lint `HardcodedText` = error); TalkBack pass on every screen; 48 dp touch targets; font-scale 1.3 doesn't clip |

"Completed AAA" = all gates green **plus** a final re-audit pass confirming no new Critical/High findings.
